# 0095: crossbar bring-up after link configuration (uninstalled)

0094 trains the right USB4 link and accepts a 2560x1440 modeset, but Oliver
confirms no picture. Hyprland reports page-flip pending and EBUSY. A ten-second
isolated trace at uptime 596 seconds contains 1587 frame events from only
one DCP pointer (likely the active internal panel); this does not establish
which external submission stalled because tracing began after modeset.
No register read/write or modeset was initiated for this trace.

Offline native 13.5 kernelcache analysis identifies this sequence:
AppleATCDPPort::didChangeLinkConfiguration block 0xfffffe00093a2a18 checks
cached link rate at object+0x248 and invokes vtable+0xa08 when nonzero.
The DPIN vtable maps that slot to bringConnectionUp at 0xfffffe000939a0f8.
This invokes inherited bring-up then the previously analyzed DPIN active
handshake. willChangeLinkConfiguration at 0xfffffe00093a2110 invokes
slot0xa00 (DPIN takeConnectionDown) only if the OLD cached rate is nonzero.
The first zero-to-HBR transition therefore needs bring-up on completion.
Linux's DID_CHANGE callback currently only delays 10 ms.

Native T602X crossbar bringConnectionUp block 0xfffffe000938b97c separately
programs FIFO clocks. Its pclkForConnection at 0xfffffe000938ccac returns
clock1 for DPIN0 (downstream role1). Thus the initial hypothesis of the
wrong clock branch is NOT supported for this route. The matching source
selector for dcpext1,0 is 2. No new clock register values are proposed.

0095 adds one guarded reselect of the existing right crossbar at the first
DID_CHANGE with nonzero cached link rate, through the same native helper
used by ACTIVATE. The existing ACIO owner returns cached active success;
no second DPIN activation handshake is intended. A per-port attempted latch
refuses subsequent nonzero DID_CHANGE calls with EALREADY. This tests the
missing sequencing boundary without implementing repeated link cycles.
It is NOT equivalent to the full native down/up lifecycle and is not a
proven fix. It still uses the existing experimental crossbar implementation.

0094 logged callbacks 5/12/9/6 at 269.474..269.475 seconds, followed by
training completion and timing delivery, so this boundary actually occurs.
No post-request hotplug retry or manual tunnel is introduced. Default-off,
j416s, right typec2, dcpext1, unit0, ABI13.5 and no physical PHY guards remain.
