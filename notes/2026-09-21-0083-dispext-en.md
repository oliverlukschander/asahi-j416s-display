# 0083 T602x crossbar dispext enable on dpin0

0082: firmware powers nub, `pmgrResetDevice 0x25`, ACTIVATE, then
waits. Analog `+0x18=0x17`. Crossbar dump after `Switched dpin0`
had `050=00000000`.

t8103 sets `CROSSBAR_DISPEXT_EN` (0x050) to the dispext bit when a
route is enabled. T602x never wrote it, so dpin0 was selected with
no source into the ACIO analog PHY.

0083: set 0x050 on dpin enable. After `request_display` resets pmgr
0x25, deselect and select the dpin mux again.

Keep skip lpdptxphy, unit 0, unk `0x100`. No ATC AUX. No
`core+0x10`.

Load with hub unplugged. Plug USB-C Right only after eDP-1 is up.

Watch: `t602x dpin0` `050=` not zero, `reselect dpin after nub`,
`SET_LINK_RATE`, analog `+0x18`, DP IN `DPRX`.

## Boot (hub after eDP)

eDP-1 stayed on. Hub `0-1` `0x5a:0xde81`. VMM7100 USB up. Tunnel
`0:5 ↔ 1:19` VE=AE=HPD=1 DPRX=0. Hyprland eDP-1 only.

```
Switched dpin0 to dispext1,0
t602x dpin0: ... 030=00002002 034=00000001 050=00000000
validate/connect unk=0x100/set_hpd 0
pmgrSetPowerState 0x25 mode 0xF, pmgrResetDevice 0x25
GET_SUPPORTS_HPD=1, APCALL 0 ACTIVATE, request_display 0
reselect dpin after nub: 0
t602x dpin0 after reselect: 050=00000000
analog +0x18=0x1017
```

`0x050` readback stays 0. Same class as `0x070`: T602x ignores
that t8103 enable. Reselect restored the same dpin programming.
No `SET_LINK_RATE`. Analog is back to the 0079 waiting value
`0x1017`.

Closed: `CROSSBAR_DISPEXT_EN` is not the T602x source enable.
The registers that stick (`0x000`–`0x034`) are already programmed.
