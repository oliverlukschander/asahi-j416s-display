# 0084 set_hpd after nub starts DCPDPDevice

Re-arm while the 0x9001 nub was already up (eDP stayed on):

```
DCPDPDevice:0x48 init
DCPDPDevice:0x48 attach to AppleDCPDPTXController:0x14 : 1
DCPDPDevice:0x48 start
set_hpd: -110
... ~5 s ...
APCALL 22 DEVICE_NOT_RESPONDING
DCPDPDevice stop / detach
APCALL 24 DEVICE_NOT_STARTED
```

The first set_hpd (before request_display) does not create this
device. The second one does. 0074 saw only the -110 and 22/24.
The device starts and the PHY does not answer.

0084: keep the 0079 bind, then after request_display enable USB-C
ATC DP AUX (no SS lane switch) and set_hpd again so DCPDPDevice
starts with that AUX block up.

Load hub-unplugged. Plug USB-C Right only after eDP-1 is up.

Watch: `DCPDPDevice`, `ATC AUX before DCPDPDevice`, `SET_LINK_RATE`,
analog `+0x18`, DP IN `DPRX`. eDP must stay on.

## Boot (hub after eDP)

eDP-1 stayed on. Hub and VMM7100 USB up. Tunnel `0:5 ↔ 1:19`
VE=AE=HPD=1 DPRX=0. Hyprland eDP-1 only.

```
request_display 0
pmgrSetPowerState 0x25 mode 0xF, pmgrResetDevice 0x25
reselect dpin 0
ATC AUX before DCPDPDevice: 0
DCPDPDevice:0x48 init / attach to DPTXController / start
5 s timer armed
set_hpd after nub: -110
DCPDPDevice message -535736286
APCALL 22, stop, detach, APCALL 24
analog +0x18=0x17
```

ATC AUX is up and the device still does not finish start. The
5 s timer is firmware's own start timeout, not the AFK -110.
No `SET_LINK_RATE`.

Closed: USB-C ATC AUX is not the PHY `DCPDPDevice` starts.
Analog `0x1017` (0079/0083, no ATC AUX) is the better waiting
state. Live handshake goes back to set_hpd only before the nub.
