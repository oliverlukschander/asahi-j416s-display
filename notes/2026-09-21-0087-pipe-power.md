# 0087 runtime dcpext pipe power

Every working Apple Silicon external display in Linux is DP alt
mode (fairydust): ATC PHY in DP, HPD, then the same power-on the
panel uses. That drops USB4, so it cannot drive this hub.

`iomfb_poweron` on dcpext uses handle 2 and does not set
`fDisplayPowerState`. 0087 does not call that. Writing
`appledrm.usb4_pipe=1` after boot runs handle 0 (the panel
sequence) on the armed dcpext, reselects dpin, and asserts HPD.
No modeset. No lpdptxphy. Default is 0, so boot does not call it.

## Boot result

eDP-1 stayed on. Hyprland is still eDP-1 only.

`usb4_pipe=1` returned in the same millisecond (`10000 ms remaining`).
No `set_run_mode`. No `set_device_enabled`. Crossbar after reselect:

```
000=00000004 800=00000000
020=00000001 820=00000000
```

`DCPDPDevice:0x4a` still died at 5 s (`0xe0115022`). `set_hpd` then
returned 0. No `SET_LINK_RATE`.

Handle 0 does not power this dcpext. Handle 2 (`iomfb_poweron`) was
already tried and did not set `fDisplayPowerState`. Do not call it
again.
