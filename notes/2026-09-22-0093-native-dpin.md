# 0093: native DP-IN activation candidate (not hardware tested)

## New evidence from this M2's preserved Apple kernel cache

The working macOS captures established the separate DP-IN resource at
0x701e50000, distinct from RC+0x4000. The machine also retains the matching
macOS 13.5 kernel cache at /boot/asahi/kernelcache.release.mac14j. This
provides substantially better evidence than guessing from the macOS 26
registry alone. No hypervisor or m1n1 checkout was used.

Native diagnostic strings explicitly identify DPTX_INACTIVE,
DPTX_INACTIVE_ACK and HPD_LEVEL_STATUS. The handshake has a 1000 ms deadline;
while activating, +0x00 bit 2 is the HPD condition checked during polling.
This is evidence for one missing host handshake, not proof it is the only
missing step or that the existing experimental crossbar code is correct.

## Candidate implementation

Two independently default-off, load-time-only options:

- appledrm: usb4_protocol_probe=1 and usb4_native_dpin=1
- thunderbolt_apple: dpin_native=1

The existing 0092 one-attempt route is retained, target 0x8001. Native ACTIVATE
reselects the already-owned crossbar before the handshake rather than doing
the old post-request reselect. It requires j416s, firmware ABI 13.5,
typec0, dcpext1/index2, mux index2, die0, unit0, DPIN0 and no physical PHY.
ACTIVATE/DEACTIVATE return a nonzero firmware result when the candidate
fails instead of pretending activation succeeded. Cached lane count is now
explicitly labeled cached_lanes in the probe diagnostic.

An optional exported function in the ACIO driver owns MMIO. It obtains the
correct bound platform device and uses nonblocking device and ACIO locks;
it refuses cable teardown/unbind, missing cable/NHI, wrong machine or RC
resource. Holding the ACIO lock prevents cable teardown from removing power
during the handshake. It reserves and maps only 0x701e50000..0x701e53fff,
once per ACIO instance, on first attempted activation. The one-attempt
latch survives unplug/replug. Default-off execution does not map this block.

Only +0x00, +0x0c and +0x10 are accessed. Only +0x0c bit 0 is changed.
Absent HPD prevents the activation write. The bounded wait detects HPD loss,
timeout and all-ones register reads; a failed handshake restores only the
original control bit while preserving other currently observed bits.
Deactivation requests inactive and waits for acknowledgement. Cable teardown
clears the software active state after normal ACIO poweroff.

The register handshake is shared with nine offline mock-register tests,
including absent sink/no write, invalid window, delayed ACK, deactivate,
bounded timeout, preserving unrelated hardware changes, lost HPD,
already-acknowledged state and invalid ACK. These are behavioral tests, not
proof of hardware accessibility or successful DP training.

Native +8 interrupt enables are deliberately not copied into Linux without
an interrupt handler. Existing USB4 tunnel HPD delivery and bounded polling
are used for this candidate. No analog tunables, physical-DP lane mode,
panel LPDPTX selection, timing injection, new tunnel, or panel MMIO is added.

## Validation and remaining limits

Both appledrm.ko and thunderbolt_apple.ko build against the running
7.1.12-2.5-1-ARCH build tree. The existing unused-function warning in dcp.c
and the environment's pahole-version warning are unrelated; BTF generation
is disabled for these builds. Mock tests pass with address/undefined-behavior
sanitizers. Patch whitespace and checkpatch are checked before committing.

No module installation, reload, parameter change, mapping, MMIO access or
reboot has been performed. This is a lab candidate, not a completed Linux
DP-IN driver or a verified display fix. Hardcoded machine/resource guards,
use of the existing experimental crossbar/tunnel, no new IRQ handler, and
unverified firmware target remain explicit limitations. Do not generalize
it to other ports/machines or enable it by default.

The live Sept 22 boot d1045ee5-d459-4fa1-8175-76725cee1e07 has the hub on
RIGHT typec2, NHI 0xf01f00000, crossbar 0xf0304c000. It must be unplugged
before installing/booting a candidate. The planned first native-handshake
test uses LEFT-BACK typec0 after eDP is visibly up. Never assume the live
port; confirm new dmesg and refuse the right/front routes.

Before any installation/reboot or test, record exact commands, candidate
hashes, backups and addresses in ACTION-LOG, commit and push. Preserve the
existing panel/keyboard constraints. A successful handshake alone is NOT
success: require actual link callbacks, DPRX and monitor video with eDP and
hub keyboard working. No further hardware test is implied by this build.
