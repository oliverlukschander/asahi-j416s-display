## The bandwidth grant demonstrably worked

Host DP IN adapter status at101.115s (before DPRX_DONE, right after tunnel
activation): `STAT=24000000`. Bits31:24 (`DP_STATUS_ALLOCATED_BW`) = 0x24 --
nonzero, where every prior capture (0104,0107) showed `STAT=00000000`. This
is the exact field `dp_bw_grant`'s `usb4_dp_port_allocate_bandwidth()` call
writes, and it changed exactly as designed: the connection manager has now
granted real, nonzero bandwidth to this DP tunnel for the first time in this
entire investigation. The DP-IN hop packet counter also reads nonzero
(0x00003740), consistent with0106/0107.

The hub DP OUT adapter's own local `STAT=04000000` is unchanged from prior
captures -- expected, since `dp_bw_grant` only ever writes the DP IN side's
register (that is where the USB4 spec puts this field); the hub's own local
status field is separate hub-side state, not something this patch touches
or should be expected to change.
