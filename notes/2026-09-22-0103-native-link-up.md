## Specific sequencing hypothesis

Current DID_CHANGE calls dptxport_native_dpin(active=true), which calls
mux_control_deselect/select. With0102 this runs AFTER PLL success and while
the DPIN active handshake is already cached. It tears down source clocks,
asserts FIFO resets, clears the route, then rebuilds it. The native initial
zero-to-nonzero link transition instead calls bringConnectionUp on the
already-selected route. Its T602x block938b97c performs the up sequence;
there is no corresponding disconnect inside that bring-up. This difference
is concrete, but its causal role in no-signal is not proven.

0103 changes only the tunnel-clock-enabled DID_CHANGE path to an optional
crossbar-owner bring-up operation. The helper requires j416s, the exact
right resource f0304c000, T602x mux, DPIN0 selectedsource2 and one attempt.
Caller retains firmware13.5/DCP2/unit0/die0/right route/DPINindex1 checks,
plus a successfully configured saved clock PHY and nonzero link rate.
ACTIVATE and ordinary mode selection remain unchanged. This is a focused
sequencing test, not a complete port of the native crossbar lifecycle.

Native clock1 bring-up sequence938bc80..938bdf8:
clear reset bits +004/bit2,+014/bit2,+024/bit0; wait1us; verify their
status+804/bit2,+810/bit2,+81c/bit0 cleared. On failure return-ETIMEDOUT.
Then set+008/bit2; masked selector+018/bits5:4=1; +028/bits1:0=1;
set+000/bit2,+00c/bit2,+01c/bit0,+034/bit0,+02c/bit2.
Do not disconnect/rewrite+030; do not assert resets or clear source clock;
no legacy+050/+070 writes from this new operation. Unrelated bits preserved.
The normal dump afterward uses the existing snapshot registers. No mapping.
Native cycle-slip-workaround branch is not enabled for this model; no
speculative source-clock pulse added. Existing DPIN active call remains
cached by the ACIO owner, matching current behavior after bring-up.
