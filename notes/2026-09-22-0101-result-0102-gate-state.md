## 0102 candidate, not installed or hardware-tested

Kernel commit beef385; exported patch0102. Retain all original mode,
resource, route, machine, firmware, one-attempt and rollback restrictions.
Read and log all four preflight registers before deciding:7000,2200,2000,
7044. The first three are existing reads moved ahead of early returns;
7044 gets an extra preflight read through the existing ATC mapping, in
addition to the original post-command lock poll. No added write/mapping.

Permit the EXACT extra gate value0x0000e001, only if PLL output enables
(+2200 mask54), command request(+2000 bit0), and lock(+7044 bit3) are all
clear. Other enabled-gate values remain rejected. Lock clear is a new,
stricter prerequisite for both accepted gate cases. This is a bounded
experimental exception, not a full clock-client ownership implementation.
We have not established that the hardware passes these remaining guards.

Existing native descriptor/rate programming and write masks are unchanged.
In the e001 case PCLK2/DPRX enables remain untouched, as in the native
RMW sequence; saved PCLK1 state is restored on cleanup. The already
asserted byte-clock reset bit0 is also preserved. No direct-PHY rate
configuration or USB4 lane switch is introduced. Full native teardown
and multiple concurrent clock clients remain outside this experiment.

Tests compile actual helpers with RAM MMIO and UBSan:4 rates x2 initial
states (gates clear/e001), all4 timeout points in each, exact rollback,
idempotence, rate-change refusal,8 busy guards, all32 single-bit variants
of e001 rejected, e001 plus each PLL-output/request/lock conflict rejected.
Write allowlist and preservation of unrelated changes pass. PLL lock is
simulated after command0, not incorrectly present at initial preflight.
Hardware behavior remains unverified. Kernel/local helper blocks identical.
